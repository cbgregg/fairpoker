How the shuffle is proven

  1. 1
    Commit

    The table draws a secret 256-bit server seed and shows you its SHA-256 fingerprint before the deal.

  2. 2
    Shuffle

    HMAC-SHA256 of your client seed and the hand number, keyed by the server seed, drives a Fisher-Yates shuffle. Neither seed alone decides the deck.

  3. 3
    Reveal

    When the hand ends the server seed is published. Recompute the fingerprint and the deck in the Fairness panel, or with any SHA-256 tool.

COM players play blind to you. Each decision uses only that seat's two cards, the board, the pot and the betting. The dealer's riffle on screen is for show; the deck order comes from the seeds. This table runs in your browser, so the seed is held locally rather than on a remote server.

Verify hand

    Exact algorithm
    commitment = hex(SHA-256(utf8(serverSeed))) for block i = 0,1,2,… mac_i = HMAC-SHA256(key = utf8(serverSeed), msg = utf8(clientSeed + ":" + nonce + ":" + i)) words += mac_i read as 8 big-endian uint32 deck = [0..51] card = rank*4 + suit rank 0..12 = 2..A, suit 0..3 = ♠ ♥ ♦ ♣ for i = 51 down to 1, w = 0,1,… j = floor(words[w] / 2^32 * (i+1)); swap deck[i], deck[j] deal from deck[0]: hole cards one at a time clockwise from the seat left of the button (two passes), then burn, flop ×3, burn, turn, burn, river
